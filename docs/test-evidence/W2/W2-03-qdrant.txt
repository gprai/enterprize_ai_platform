W2-03 — INTERNAL-ONLY QDRANT
============================

BUSINESS PURPOSE
Qdrant provides a real local vector-store integration boundary for the
retrieval contract without deploying a cloud service or exposing the local
database through a host port.

ARCHITECTURE POSITION
Qdrant and a profile-controlled, one-shot test runner share only the Compose
logical network qdrant_internal. The network remains internal: true, and
Compose generates its project-scoped runtime name. Qdrant has persistent
storage only for the life of the owner-controlled test project; the runner
has no persistent storage.

FAIL / REMEDIATION HISTORY
Initial host-side health requests failed even though Qdrant was healthy.
Docker recorded a requested HostConfig binding on the internal-only network
but no effective host endpoint. The owner chose not to weaken the network.
The approved remediation removed host publication and moved the integration
test into the internal one-shot runner.

The earlier runner build used an external Dockerfile frontend, installed
packages with root pip outside a virtual environment, and selected UID/GID
65532, which produced a range warning. The approved remediation removed the
frontend directive, added an internal virtual environment, and selected
UID/GID 10001. The final rebuild had none of those three warnings.

- Compose advised placing --progress as a global option; the build passed.
