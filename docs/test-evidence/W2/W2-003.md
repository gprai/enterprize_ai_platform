## Business purpose

W2-003 establishes a secure local ingestion boundary for enterprise retrieval. Its business value is that a document must prove its source, tenant, classification, access rules, file safety and PII treatment before any text can be tokenized, embedded or written to a vector store.

This reduces the risk of indexing the wrong tenant's content, storing regulated data without approval, losing document provenance, or reporting a rollback as successful when cleanup cannot be proven.

## Architecture position

W2-003 sits between approved source documents and the retrieval storage contracts created in W2-001. It consumes the W2-002 embedding and tokenizer identity while ordinary tests continue to use deterministic fakes.

The approved local flow is:

1. Load the strict corpus manifest and PII policy.
2. Resolve a relative source beneath the approved source root.
3. Reject traversal, symlinks, unsupported types, oversized files and unsafe PDFs.
4. Hash the original bytes and derive deterministic document and version identities.
5. Normalize text without changing the authoritative byte hash.
6. Inspect PII before tokenization, embedding, telemetry output or storage.
7. Quarantine high-risk content or apply exact typed redactions.
8. Revalidate tenant, ACL and any time-bounded exception.
9. Tokenize, chunk, embed and upsert through provider-neutral contracts.
10. Compensate only the uncertain document version when a final upsert may have partially succeeded.
11. Return a strict redacted JSON manifest.

## Implemented local scope

- Exact synthetic corpus and five-question starter fixture.

- Dual `INGESTOR + ADMIN` authorization for exact PII exceptions.
- Sequential ingestion, bounded batches, retries, deadlines and exact-version compensation.
- Fake, Qdrant and OpenSearch provenance and version-deletion consumers.

## Decisions and trade-offs

- Original bytes, rather than normalized text, determine content identity so line-ending-only changes remain auditable.
- Sequential processing limits throughput but reduces memory pressure and mutation blast radius.
- A 200-token target and 25-token overlap preserve context across boundaries at the cost of additional vectors.
- Quarantine stores only status, not a copy of rejected content, reducing privacy residue.
- Exact-version compensation protects an earlier valid version while removing a possibly partial new version.
- Offline real-tokenizer evidence proves tokenizer compatibility only; it does not prove real embedding or vector-service behavior.

## Layman explanation

The ingestion pipeline acts like a secure mailroom. It checks that each package came from an approved sender, belongs to the correct department, is a safe size and type, and contains no restricted information before copying it into a searchable filing cabinet. If copying might have failed halfway, it removes only that uncertain copy and leaves the previous approved copy intact.
