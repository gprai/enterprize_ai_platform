## Business and architecture outcome

The implemented flow is:

`authorized event → strict EventBridge-compatible envelope → authorization and provider admission → idempotency and tenant quota → approval when required → bounded task execution → success, denial, timeout, cancellation, compensation, reconciliation, or dead letter → hash-linked audit trail`

In plain language, this is a tracked parcel workflow. Every handoff, exception,
approval, retry, and terminal destination has a named state. A parcel cannot be
silently rerouted to another tenant, provider, or workflow, and an uncertain
delivery does not become an automatic duplicate shipment.

The implementation is provider-neutral and source-only. It defines compatible
contracts for EventBridge events and Step Functions-style durable states but
does not create or call either AWS service. It also does not create a second
API, bypass the existing authorization architecture, or replace W8-001 serving
and W8-002 inference reliability ownership.

## Workflow, state, and adapter contracts

Three workflow kinds are admitted:

| Workflow kind | Task timeout | Workflow timeout | Approval rule |
|---|---:|---:|---|
| Asynchronous inference | 120 seconds | 300 seconds | Sensitive classification or high cost requires approval |
| Long-running ingestion | 120 seconds | 900 seconds | Sensitive classification or high cost requires approval |
| Model training | 60 seconds | 21,600 seconds | Approval is always required |

The explicit states are `RECEIVED`, `AUTHORIZED`, `IDEMPOTENCY_RESERVED`,
`QUOTA_RESERVED`, `AWAITING_APPROVAL`, `READY`, `RUNNING`, `RETRY_WAIT`,
`RECONCILIATION_REQUIRED`, `COMPENSATING`, `SUCCEEDED`, `DENIED`, `TIMED_OUT`,
`CANCELLED`, `COMPENSATED`, and `DEAD_LETTERED`. The final six are terminal.
Illegal transitions, terminal-state mutation, revision conflicts, and more than
32 transitions fail closed.

`OrchestrationEngine` composes injected protocols rather than cloud SDKs:

- `AuthorizationGate` validates workflow, tenant, subject, authorization
  reference, and classification before state or provider work;
- `StateStore` creates, loads, and compare-and-swaps versioned state;
- `IdempotencyStore` binds one idempotency key to one canonical request;
- `QuotaGate` reserves and releases per-tenant/global capacity;
- `ApprovalGate` returns a bound, expiring independent decision;
- `TaskExecutor` returns an explicit success, retryable/permanent failure,
  partial effect, or unknown-outcome disposition;
- `AuditSink` records content-free, hash-linked transitions;
- `DeadLetterSink` records exact failed work; and
- `Compensator` applies an explicit compensating action to a recorded effect.

The EventBridge-compatible envelope accepts only the three named detail types,
`ap-southeast-1`, matching UTC event/request timestamps, and at most eight
unique resource references. Requests and state carry hashes or governed
identities rather than raw business payloads. Canonical compact sorted UTF-8
JSON provides deterministic request, policy, state, and transition identities.

## Bounds, retry, approval, and recovery

| Control | Implemented value |
|---|---:|
| Maximum event/state size | 65,536 bytes each |
| Maximum transitions | 32 |
| Maximum cumulative fan-out | 8 |
| Maximum active workflows | 4 global / 2 per tenant |
| Maximum pending per tenant | 8 |
| Maximum attempts | 3 total |
| Retry delays | 1 second, then 2 seconds; multiplier 2; no jitter |
| Approval validity | 600 seconds |
| State/audit retention design | 30 days |
| Dead-letter retention design | 7 days |

The shared attempt and fan-out budgets include adapter-reported consumption,
so an adapter cannot hide downstream retries or fan-out. Retryable failures
receive only the configured delays and dead-letter after exhaustion. Permanent
failure dead-letters immediately. Partial effects enter compensation. An
unknown outcome or unavailable dead-letter sink enters
`RECONCILIATION_REQUIRED` with a bound resume token; it is never retried
automatically. Resume requires matching workflow identity, revision, token,
authorization, and an explicit `retry`, `compensate`, or `dead_letter` action.

Admission can be withdrawn before new work. Authorized cancellation is
terminal and idempotent. These are source-level recovery contracts, not a
deployed drain, operational rollback, or cloud teardown.

## Security, privacy, provider, and cost controls

- Authorization and clearance are checked before state creation, idempotency
  reservation, or task dispatch. Cross-tenant and insufficient-clearance
  requests fail closed.
- Approved model workflows reuse W8-001 `ArtifactIdentity`, request
  authorization, and deterministic routing. Pending artifacts or a substituted
  provider are rejected before idempotency or execution.
- Confidential/restricted work, high-cost work, and every training workflow
  require approval. The requester cannot approve the same workflow, and an
  approval is bound to tenant, requester, request identity, decision time, and
  exact expiry.
- Audit and dead-letter records contain pseudonymous SHA-256 references and
  safe reason codes. Tests verify that raw tenant/subject values, prompts, and
  document content are absent. Hashes remain pseudonymous, not anonymous.
- The W8-002 provider-circuit contract remains owned by `w8-002-serving` with
  threshold 5, 30-second open duration, and one half-open probe. W8-003 does
  not create a second provider circuit.
- Live execution is `NOT_AUTHORIZED`, provisioning is `NOT_RUN`, and the live
  cost ceiling remains `OWNER_BINDING_REQUIRED`. Local workstation time, CPU,
  memory, disk, and owner effort were not monetized and are not represented as
  zero.
