## Business use case

W1-003 gives the owner a consistent way to test changes before accepting them. Tests are separated by purpose, cloud and paid checks are disabled by default, external providers can be replaced with deterministic fakes, and a redacted evidence summary can be produced without writing secrets or document content.

This reduces the business risk of approving a change based on an incomplete test, accidentally incurring cloud cost, or treating a local result as proof of deployment.

## Architecture position

W1-003 is the quality-and-evidence control layer between approved requirements and later release decisions. It validates repository behavior and records test metadata. It does not retrieve documents, call a model, operate Qdrant or OpenSearch, deploy infrastructure, or approve production use.

A **deterministic fake provider** is a local test replacement that always returns controlled results. It makes failures repeatable and avoids relying on a live external system. A **pytest marker** is a label used to select or exclude a category of tests.

## Implemented scope

- Pytest categories for unit, integration, contract, feature, smoke, security, and teardown tests.
- Automatic category markers based on test-directory placement.
- Default exclusion of AWS and paid tests.
- Deterministic fake clock, Git metadata, environment, and answer providers.
- A stdout-only JSON evidence recorder with validation and redaction.
- A sample feature test mapped to the approved `MVP-001` feature ID.
- Repository cleanliness checks for tool caches, `.deepeval`, premature evidence, and unmanaged service or infrastructure artifacts.
- Default suppression of DeepEval's automatically loaded `deepeval` pytest plugin.

## Technical importance

The controls make test execution reproducible, cost-aware, and auditable. Default marker exclusions reduce accidental cloud access, fake providers remove nondeterministic external behavior, scoped linting separates current work from historical debt, and the evidence contract prevents arbitrary or sensitive content from entering the test record.

## Layman explanation

The repository now has labeled testing lanes. Ordinary local checks can run safely, while AWS and paid lanes stay closed unless the owner deliberately opens them. The evidence recorder acts like a receipt printer: it reports what was tested and the result without copying sensitive business documents into the receipt.

## Interview talking points

1. **Why exclude AWS and paid tests by default?** Explicit opt-in prevents accidental cost, credential use, and external side effects.
2. **Why use deterministic fake providers?** They make tests repeatable and allow local validation when external systems are unavailable or unapproved.
3. **Why separate test categories?** Unit, integration, contract, feature, smoke, security, and teardown tests answer different risk questions and make failures easier to diagnose.
4. **Why record `UNCOMMITTED` instead of inventing a Git SHA?** Honest provenance is more valuable than a false identifier; Git state can be recorded separately until a commit exists.
5. **What did the DeepEval issue teach?** Installed plugins can create side effects before application tests run, so third-party pytest entry points must be identified and disabled unless explicitly needed.
