W11-002 implements a source-only fire-drill framework: marked rooms, observers
and an emergency stop, not setting the whole building alight. The local PASS
proves deterministic in-process detection, abort, restoration and residue
contracts. It does not prove a live dependency outage, production resilience,
alarm delivery, AWS authorization, deployment, recovery time or cloud cost.

## Architecture and producer-consumer flow

```text
approved hypothesis + one bounded scenario
  -> strict W11 policy and pinned W6/W11/FIS source identities
  -> preflight telemetry, safety, target, duration and cancellation checks
  -> injected in-memory fault only
  -> before/after SLI and synthetic-alert observation
  -> immediate abort on telemetry loss, unsafe state or exceeded boundary
  -> exact local restoration
  -> recovery and in-memory residue proof
  -> PASS / FAIL / NOT RUN / INDETERMINATE result

separately approved live FIS action -> NOT RUN
```

- `configs/chaos/controlled-dependency-chaos.yaml` is schema
  `w11-002.controlled-dependency-chaos.v1`, classification
  `source-contract-not-live-evidence`, environment `sandbox`, Region
  `ap-southeast-1`, execution mode `synthetic-in-process-only`, and live status
  `NOT RUN`.
- `src/enterprise_ai_platform/chaos.py` strictly loads the policy, normalizes
  scanner-safe grouped SHA-256 values, verifies the current upstream FIS, SLO,
  template and IAM bytes, exposes injected fault/observation/clock ports, and
  returns an `ExerciseResult`. It has no AWS SDK, network, subprocess,
  Terraform, Kubernetes or live-FIS execution path.
- `tools/chaosctl.py` exposes only `validate` and one-scenario `rehearse`.
  Validation and rehearsal print JSON to stdout; there is no live-execution
  verb and no evidence file is written.
- `feature-matrix.yaml` binds the work to blocked features `FIS-002` and
  `RES-002`. The Makefile and platform validator expose exact validation and
  focused-test consumers. W5 composition and protected-identity consumers were
  updated so the new source and changed governance bytes remain covered.
- Existing FIS, SLO, alert, Terraform template and IAM files are pinned
  upstream producers, not duplicated or rewritten by this task.

The policy permits exactly one scenario and one target for at most 300
seconds. Its local deadline is 30 seconds and retries are zero. It stops for
missing or stale telemetry, unsafe state, target/scenario excess, deadline
excess, cancellation, or unverified recovery/residue. The 13 ordered synthetic
scenarios cover EKS pod loss, simulated node loss, Bedrock timeout and
throttling, OpenSearch unavailable and stale response, S3 unavailable and
partial failure, inference timeout and partial failure, network timeout,
telemetry loss, and unsafe state.

Telemetry loss remains `INDETERMINATE` for the SLI and cannot be represented
as a healthy measurement or delivered alert. Unsafe state is a failed safety
observation. Missing preflight telemetry prevents injection. Any observation
or restore failure blocks local PASS, and failed restoration preserves a
failed residue result rather than claiming cleanup.
