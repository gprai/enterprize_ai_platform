BUSINESS PURPOSE

W4-01 provides a bounded HTTP interface for health and governed query access.
The boundary is disabled by default so the approved legacy health-only
application remains the normal behavior. When explicitly enabled, it adds
typed health and query routes without adding public ingress, CORS, proxy trust,
live providers, service deployment or agent execution.

IMPLEMENTED API CONTRACT

Legacy health compatibility

- GET /health retains its existing status and exact body fields: status,
  service and environment.
- The default api_routes_enabled=false behavior adds no W4 route state or
  request-ID header and does not resolve injected dependencies.

Enabled health routes

- GET /health/live proves only that the application event loop can answer. It
  makes no dependency, RAG, retrieval, provider, vector-store, network or cloud
  call.
- GET /health/ready calls exactly one injected local query-wiring probe under a
  one-second timeout. A false result, exception or timeout returns 503
  service_not_ready. It does not probe Qdrant, OpenSearch, Bedrock, a model,
  AWS, cloud or any network service.

Strict query transport and response

- POST /v1/query accepts HTTP application/json only and rejects unsupported
  media types or content encodings before authentication-dependent work.
- The implementation streams and counts raw body bytes before full JSON or
  Pydantic processing and rejects bodies larger than 131,072 bytes.
- Strict JSON parsing rejects malformed data, duplicate keys, non-finite
  numbers and invalid UTF-8.
- The request schema permits only query: str. Unknown fields, wrong types and
  missing query data are rejected. The raw query is passed to the existing RAG
  boundary with logical content_type=text/plain.
- The existing 10,000-character logical guardrail remains downstream and
  returns the existing guardrail_input_invalid safe code.
- Answered and abstained responses return only server request identity and
  trusted normalized result fields. Existing Citation and Usage contracts are
  reused; absent model or retriever versions are not invented.

Request identity

- Every W4-enabled response, including errors, receives a new server-generated
  UUIDv4 in X-Request-ID and the response body.
- Inbound X-Request-ID, X-Correlation-ID and X-Forwarded-* values are not
  trusted as the server identifier. No proxy-trust boundary was added.

Deadline, overload and cancellation

- The query boundary admits at most four in-flight queries per application.
- Capacity acquisition is atomic and non-waiting. There is no hidden queue and
  no API-level retry.
- Exhausted capacity returns 503 api_overloaded, retryable=true and
  Retry-After: 1 without a RAG call.
- Admitted RAG work uses the existing request deadline. Capacity is released in
  finally for answer, abstention, domain error, timeout and cancellation.
- Cancellation propagates and starts no replacement or background work.

Safe errors and disabled agent

- Approved transport, guardrail, vector-store, embedding, RAG, LLM, deadline,
  readiness, overload, route and internal failures are normalized into the
  safe request-ID error envelope. Raw exception content is not returned.
- POST /v1/agent returns 501 agent_disabled and calls no authenticator, RAG,
  retriever, provider, graph, approval store or tool.
