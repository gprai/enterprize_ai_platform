# W4-002 — Bounded agent controller implementation and evidence

## Business purpose

W4-002 adds controlled agent behavior without granting uncontrolled autonomy. The delivered boundary makes every agent action follow an explicit graph, separates authentication, authorization and human approval, limits resource use, and prevents a model proposal from becoming trusted authority.

This is the primary implementation and evidence handover for `AGENT-001`. The feature remains **In Progress**, follows `API-001`, and retains the tracker steps in this exact order: `W4-03`, `W4-04`, `W4-05`, `W4-06`, `W4-07`, `W4-09`.

## Delivered scope

The implementation provides:

- a default-off, nine-node LangGraph controller using LangGraph 1.2.11 `context_schema` and no LangGraph checkpointer or retry policy;
- an injected, fake-only `AgentEvidenceGateway` boundary rather than copied W2/W3 RAG, retrieval, citation, guardrail or provider logic;
- the `get_service_status` v1.0 read tool with exact argument `{"component":"query_wiring"}` and an injected local status provider;
- the `mock_set_service_mode` v1.0 mock-write tool with exact argument `{"mode":"maintenance"}` and a simulated outcome only;
- application-owned standard-library SQLite persistence for bounded, redacted state and approval decisions;
- durable same-tenant, different-subject human approval with UUIDv4 identifiers, ten-minute expiry, canonical fingerprint binding and atomic one-time consumption;
- strict step, tool, provider, token, retry, deadline, state-size and concurrency budgets;
- an enabled `/v1/agent` start/decide boundary while preserving the W4-001 disabled `501 agent_disabled` behavior and `/v1/query` contract.

The safe defaults are `agent_enabled=false` and `agent_mock_write_enabled=false`. No live adapter, real write tool, external approval service, production identity provider, model, vector service or telemetry implementation was added.

## Security, privacy and failure behavior

Trusted identity comes from the existing `AuthContext`, never from request JSON. Read authority requires `READER`; mock-write request authority requires same-tenant `ADMIN`; approval requires same-tenant `REVIEWER` and a different subject. Model intent grants no authority. Denial occurs before gateway, store or tool activity.

Approval and state records contain UUIDs, versions, counters, bounded safe codes and hashed references. The hashes are pseudonymous, not anonymous. Raw prompts, evidence, answers, tool output, credentials, PII, provider envelopes, exception content, stack traces and chain-of-thought are excluded. Corrupt, inconsistent, oversized, duplicate-key, non-finite, invalid-UTF-8 or version-mismatched records fail closed.
