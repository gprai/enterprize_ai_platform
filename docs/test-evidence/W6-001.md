## Two-stage image binding

Stage one validates the repository source template. The exact image value in
that template is the deliberately invalid sentinel
`enterprise-ai.invalid/w6-001:OWNER_BINDING_REQUIRED`. A successful stage-one
check returns **SOURCE TEMPLATE VALID — NOT DEPLOYABLE**; it does not create a
release package or contact a registry, AWS account or Kubernetes cluster.

Stage two requires owner-controlled W6-01 release evidence. The binder accepts
a closed release-binding schema, checks the source, OCI, scanner, SBOM,
provenance, image-composition, operation and owner-approval identities, and
binds the ECR repository to an exact `sha256` image digest. It generates a
canonical render and release-hash record in a new approved external output
directory. A valid output is classified **IMMUTABLE RELEASE PACKAGE VALID —
NOT DEPLOYED**. Mutable-tag release and implicit fallback are not allowed.

No W6-01 release binding was supplied during this task. No deployable package
was generated.
