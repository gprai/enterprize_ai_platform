The lay explanation is a records office that tracks every copy and destroys
only authorized records with a witnessed chain of custody. The system must
identify the precise source version, every derived index record, the archive
receipt and the one-time approval before proceeding; uncertainty leaves the
record retained and the result non-PASS.

## Architecture and producer-consumer flow

```text
W7-001 governed ingestion / W7-002 processing
  → immutable source identity and document version
  → injected Presidio-compatible analysis + Macie-compatible discovery boundary
  → CLEAR / REDACTED / APPROVED_EXCEPTION or QUARANTINED
  → existing approved embedding/index consumer
  → exact lifecycle plan + redacted metadata archive + usable retained KMS key
  → authorized index-version deletion + count-by-document-version == 0
  → exact S3 object-version deletion + exact-version absence check
  → PASS only when native absence is proven; otherwise FAIL/INDETERMINATE
```

No task-owned ingestion, retrieval, API, agent, deployment or infrastructure
path was added. `PrivacyCoordinator` combines the injected PII analyzer and
Macie protocol; `LifecycleCoordinator` consumes the vector-store count/delete
contract, versioned object-store, redacted evidence archive, KMS usability
boundary and one-time approval-use store. Fake, Qdrant and OpenSearch adapters
implement version-scoped index count proof. Re-index requests bind a source,
prior manifest, privacy assessment, quality report and a distinct new manifest.

## Owner-approved technical decisions and boundaries

- Synthetic `PUBLIC` and `INTERNAL` only, region `ap-southeast-1`; no real
  sensitive document was processed.
- Presidio remains an injected adapter boundary; Macie remains a protocol and
  deterministic fake. No model/signature download or live discovery occurred.
- Any analyzer/discovery error, identity mismatch, non-PASS/unknown discovery,
  classification mismatch, missing redaction or invalid exception quarantines.
  Findings may proceed only as `CLEAR`, `REDACTED` or an exact
  `APPROVED_EXCEPTION`.
- Evidence stores redacted metadata and identity hashes only, never source
  content. Safe reason codes do not expose provider exceptions or content.
- Retention values are raw 7 days, quarantine 7, processed 30, evidence 30.
  Sandbox/infrastructure expiry is a separate lifetime.
- Quarantine cleanup is limited to individually approved, exact expired object
  versions, sequentially. Prefix/bucket cleanup is prohibited.
- A destructive plan is tenant-, operation-, exact-plan- and exact-target-
  bound; approval is UTC, one-time, and valid for at most 15 minutes.
- Concurrency is 1. At most two attempts apply to read-only discovery;
  destructive retries are disabled. A partial outcome preserves receipts and
  remains FAIL/INDETERMINATE; resumption requires a new approval bound to the
  same plan.
- Deletion order: verify the redacted archive and usable KMS key; delete the
  exact index document version; query native adapter count and require zero;
  delete the exact source object version; verify exact-version absence.
- Re-index requires immutable approved source identity, prior manifest hash,
  full privacy and quality re-evaluation, and a new manifest identity.
- Shared buckets, collections/indexes, domains, KMS keys and service-linked
  roles are retained; W7-003 never schedules KMS key deletion.
- Feature Store, SageMaker training/endpoints, MLflow, Model Registry, Ray
  Serve and Triton remain excluded.

## Learning handover

The practical lesson is that deletion is a chain of proof, not a single API
call: retain an identity-bound receipt, prove the derived index is empty, then
delete and verify only the exact source version. An uncertain response is
`INDETERMINATE`, not success; shared keys and shared resources remain retained.
The fake-backed tests teach contract behavior only and cannot establish live
Macie, Presidio, AWS or OpenSearch readiness.

Owner teach-back remains owner-led and is not completed or inferred here. The
owner should be able to explain why index absence precedes source deletion,
why partial failures preserve receipts, why approvals expire after 15 minutes,
and why the local PASS does not prove cloud readiness.
