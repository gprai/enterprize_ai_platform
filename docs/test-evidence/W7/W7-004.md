## Business architecture and decision flow

The bounded flow is:

`measurable structured-ML reuse need → compare no store / SageMaker Feature Store / Feast → owner-approved decision → NOT ADOPTED until admission conditions are met`

The current repository flow remains the RAG-001 document ingestion,
embedding and retrieval path. W7-004 is linked as a decision/evidence step
under RAG-001; it does not create a W7-004 feature ID, feature-serving
component or feature-store integration. A feature store is not a vector store
and is not placed in document RAG.

The owner-approved comparison is recorded in [ADR-018](../../adr/ADR-018-feature-management-decision.md):

- **No store — selected now:** avoids unused infrastructure while no qualifying
  producer, consumer, reusable feature set and measurable online/offline need
  have been established.
- **SageMaker Feature Store — conditional candidate:** preferred only if a
  proven use case is AWS-first and the owner approves its access, region, cost
  and lifecycle.
- **Feast — conditional candidate:** considered only if provider portability
  is an explicit requirement for a proven use case.

The plain-language analogy is choosing whether a shared pantry is justified
before building and stocking one. The pantry is not useful merely because it
can be built; first identify who supplies it, who uses it, what must be kept
fresh and who pays for and cleans it.
