# W7-001 — Governed Data Foundation and Ingestion Evidence

## Business outcome

W7-001 adds a deterministic governance boundary between source acquisition and
the existing RAG-001 embedding and indexing pipeline. A document cannot become
eligible for embedding until its source identity, tenant, classification,
residency, retention, idempotency identity, malware result and PII disposition
have passed the local contracts.

The business flow is:

`versioned source object → raw zone → strict metadata validation → replay or conflict decision → malware decision → PII decision → quarantine or processed handoff → embedding eligibility → existing ingestion pipeline → indexed audit state`

In plain language, this is an airport baggage system: every item is labelled,
screened and either quarantined or cleared before it can be loaded. A direct
source-to-index route is not approved.

## Implemented architecture and contracts

The implementation extends RAG-001 rather than creating another ingestion
platform. `configs/ingestion/w7-001.yaml` fixes the local boundary to synthetic
PUBLIC and INTERNAL data in `ap-southeast-1`, using the existing sandbox
bucket and four policy-isolated prefixes:

| Zone | Prefix | Object retention |
| --- | --- | ---: |
| Raw | `raw/` | 7 days |
| Quarantine | `quarantine/` | 7 days |
| Processed | `processed/` | 30 days |
| Evidence | `evidence/` | 30 days |

These are object-zone retention contracts. They do not extend the separately
controlled maximum 24-hour sandbox lifecycle.

The strict typed contracts cover source, governance, processing, catalog,
lineage, audit and embedding-eligibility identities. Canonical JSON is compact,
UTF-8, key-sorted, finite-number-only and terminated by exactly one newline.
SHA-256 identities bind exact canonical bytes. Audit output uses safe reason
codes and hashes; it excludes source content, PII values, malware signatures,
prompts, vectors, credentials, tokens, raw exceptions and raw cloud responses.

The deterministic state machine permits only the approved transition order:

`RECEIVED → VALIDATED → RESERVED → MALWARE_PASSED → PII_APPROVED → PROCESSED → EMBEDDING_ELIGIBLE → INDEXED`

Fail-closed terminal outcomes include `QUARANTINED`, `DEAD_LETTERED` and
`CANCELLED`. Exact replay returns the prior deterministic result without a
second transition or downstream call. Identity/content conflict, stale or
future events, malware DETECTED/UNKNOWN/ERROR, scanner failure and invalid
metadata prevent eligibility. Downstream retry exhaustion reaches
`DEAD_LETTERED`. The unchanged ingestion pipeline is called only after a valid
`EmbeddingEligibility` object exists.

Malware scanning and idempotency are protocols with deterministic local fakes.
There is no real scanner, signature service, DynamoDB or filesystem-backed
idempotency store. Glue and Step Functions are serialization/state contracts
only. EventBridge is limited to S3 notification IaC; no rule or target was
created.

Terraform source continues to use the existing platform bucket and KMS
boundary. It adds the four lifecycle contracts, S3 EventBridge notification,
prefix-scoped IAM and outputs. Retrieval access is limited to processed and
evidence prefixes; raw and quarantine remain denied. OPA and the existing
policy runner reject unapproved buckets, keys, services and prefix access.

No concurrent fan-out was introduced. Existing bounded retry, jitter,
120-second processing deadline and 60-second vector-operation boundary remain
the approved local limits.
