## Business outcome and plain-language explanation

W10-003 turns RAG release evaluation into a governed decision rather than a
collection of informal model checks. A privacy-safe golden set and adversarial
extension set are evaluated against exact model, prompt, embedding, retrieval,
reranker, policy, and dataset identities. Quality and safety thresholds then
produce a release decision that can be repeated, audited, and rolled back.

The plain-language analogy is a crash-test and quality laboratory where every
vehicle configuration is serialized before release. The test result belongs to
the exact vehicle that entered the laboratory; changing its engine, software,
parts, test track, or pass threshold creates a different identity and requires a
new test.

Beneficiaries are RAG users, safety reviewers, model-risk reviewers, release
approvers, and operators who need a precise failed identity for recovery.

## Architecture and producer-consumer flow

```text
privacy-safe quality set + synthetic adversarial set
                  |
                  v
exact model + prompt + embedding + retrieval/reranker configuration
                  |
                  v
authorized retrieval -> prompt/content separation -> Bedrock inference
                  |
                  v
grounded answer/citation/abstention checks + safety observations
                  |
                  v
canonical report identity + threshold gates + repeatability comparison
                  |
          +-------+--------+
          |                |
       release          block release
       eligible         and retain exact
                        failing identity
```

The repository-local `tools/evaluationctl.py rag-safety` bootstrap loads the
strict runner without requiring an installed editable package. The runner
accepts only the approved datasets, policy, known-good control, external output
root, AWS profile, account, region, exact runtime STS principal, active Bedrock
model/profile, pricing observation, and owner network/paid/pricing flags.

The quality dataset covers answered, abstention, expected-error, retrieval, and
release-blocking cases. The ordered twelve-case safety extension covers indirect
prompt injection, unsafe documents, malicious metadata, unauthorized tools,
approval bypass, exfiltration, sensitive output/log leakage, loop bounds, tool
timeout, partial failure, and configuration drift. Canonical JSON rejects
duplicate keys and non-finite values and produces SHA-256 identities over exact
serialized content.

- Prompt v2 requires every distinct directly responsive fact for multipart
  questions, exact evidence-verbatim extraction, and one server-resolved
  evidence reference for every evidence block used. It is a general
  completeness contract; it is not a Q39-specific answer patch.
- Model-authored short evidence references are mapped server-side to trusted

  run permits at most 30 recorded provider requests.
- Any threshold, authorization, injection, leakage, identity, repeatability, or
  drift failure blocks release and preserves the exact failed configuration.
