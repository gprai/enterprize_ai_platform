## Business outcome and plain-language explanation

W10-004 adds specialized gauges to the existing cockpit instead of building a
second cockpit. Request, model, retrieval, safety, admission, dependency,
quality, drift, and cost events continue through the existing OpenTelemetry
runtime. The change adds bounded AI-specific observations, alerts, and
dashboard panels without allowing raw prompts, raw responses, credentials, or
unbounded identifiers into telemetry.

The beneficiaries are AI service owners, SRE, security, model risk, and
FinOps. The business value is a single correlated view of whether an AI request
was safe, grounded, available, and inside its approved cost boundary.

## Architecture and producer-consumer flow

```text
request ID and runtime configuration identities
  -> API admission and authorization
  -> retrieval and RAG orchestration
  -> provider cost preflight
  -> existing OpenTelemetry runtime
  -> bounded metrics, spans, safe events, alerts, and dashboard panels
  -> operator diagnosis and an approved degraded/stop response
```

- `Settings` keeps AI operations default-off and accepts only explicit pricing
  and evaluation-identity inputs.
- `compose_aws_runtime()` loads the versioned policy, binds model, prompt,
  embedding, retrieval, and optional evaluation identities, and passes the
  existing telemetry runtime into RAG composition.
- API admission records admitted, rate-limited, backpressure, circuit-open, or
  draining states only when AI operations is enabled.
- `RAGService` preserves guardrail and authorization checks before retrieval or
  provider activity, records retrieval/model dependency outcomes, performs the
  provider/cost preflight, records token-derived cost when usage is available,
  and emits structural quality, citation, groundedness, and abstention signals.
- `OpenTelemetryRuntime.record_ai_operation()` uses the existing meter and
  span/event path. There is no second exporter, queue, collector, or telemetry
  backend.
- Prometheus rules and the existing provider-neutral Grafana dashboard consume
  the stable metric names. CloudWatch, X-Ray, Jaeger, Prometheus, and Grafana
  live delivery remains outside this source-only result.

`w10-004.ai-operations.v1`.

| Control | Exact contract |
|---|---|
| Default | `enabled_by_default: false` |
| Approved provider | Bedrock only when enabled |
| Per-successful-request ceiling | USD `0.01` |
| Pricing freshness | Maximum 24 hours; timestamps must be UTC |
| Token projection | Maximum 16,384 input and 512 output tokens |
| Quality floors | Retrieval `0.50`; groundedness proxy `1.0`; citation coverage `1.0` |
| Capture | Raw prompt and raw response capture are both `false` |
| Dimensions | `signal`, `provider`, `dependency`, `outcome`, `reason`, `evaluation_status` only |
| Protection | Encryption in transit required; existing observability RBAC |
| Retention contract | Operational telemetry 14 days; approved evaluation evidence 180 days |
| Resilience | Zero additional retries, zero query queue capacity, safe degraded mode enabled |
| Live execution | `NOT_AUTHORIZED` |

The policy loader rejects duplicate keys, YAML aliases, invalid encodings,
oversized content, unknown fields, wrong literals, and malformed values. The
provider preflight denies enabled calls for missing/stale pricing, an
unapproved provider, or projected cost above the ceiling. Disabling AI
operations preserves the established provider path.

## Decision, alternatives, and recovery

The selected direction extends the existing OpenTelemetry, Prometheus,
Grafana, CloudWatch, X-Ray, and Jaeger integration contracts. A second telemetry
stack and raw prompt/response capture were rejected because they would create
duplicate operations, conflicting identities, larger privacy exposure, and a
second retention/access-control surface.

Failure behavior is explicit:

- telemetry export loss is counted and diagnosed through the existing path;
- missing pricing, stale pricing, provider drift, or a projected cost breach
  denies the enabled call and marks safe degraded mode;
- retrieval/model dependency failure emits a bounded degraded observation and
  preserves the existing domain error;
- configuration mismatch emits drift rather than claiming the candidate is
  active;
- rate limit, backpressure, circuit-open, and draining outcomes use bounded
  admission reasons;
- disabling AI operations restores the established provider behavior without
  removing the existing telemetry stack.
