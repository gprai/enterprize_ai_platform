## Business and architecture outcome

W10-001 adds an explicit hybrid mode inside the existing authorized
OpenSearch adapter boundary. It does not create a second RAG stack. An approved
query and authorization policy produce two bounded searches: vector similarity
and lexical BM25. Both searches receive the same authorization filters. Every
provider result is reconstructed as a provider-neutral `Chunk`, reauthorized,
normalized within its channel, deterministically fused, and returned as an
existing `RetrievedChunk` with source and citation provenance intact.

The plain-language analogy is combining two ranked library catalogues while
rechecking every book's access label. One catalogue understands conceptual
similarity and the other matches exact words. Each catalogue searches only the
shelves the reader may access; the librarian rechecks every returned book;
then a fixed scoring rule merges the lists. A relevant but forbidden book is
never made safe by receiving a good score.

```text
authorized query and collection identity
  -> one provider-neutral retrieval policy
  -> identical tenant/classification/role/group/privacy filters
  -> bounded vector KNN and lexical BM25 searches in parallel
  -> strict provider-response parsing and per-result reauthorization
  -> deterministic per-channel min-max normalization
  -> equal-weight fusion and stable tie-breaking
  -> top-k provider-neutral RetrievedChunk results with provenance
```

## Exact identities, scoring, concurrency, and failure contract

The approved policy schema is `w10-001.hybrid-retrieval.v1`:

- lexical analyzer: `standard`;
- lexical similarity: `BM25`;
- vector weight: `0.5`;
- lexical weight: `0.5`;
- candidate limit: four times `top_k`, with a minimum of 20 and maximum of 100;
- concurrent channels: exactly two;
- attempts: two total attempts per channel — the initial call plus one retry;
- maximum provider search calls for one hybrid request: four;
- final order: fused score descending, lexical normalized score descending,
  vector normalized score descending, then stable chunk identity ascending.

Each channel is min-max normalized independently. If every valid score in one
channel is equal, that channel assigns `1.0` to each candidate rather than
dividing by zero. Missing membership in a channel contributes `0.0`. Duplicate
chunk identities retain the higher score only when their complete chunks are
identical; conflicting content for one identity fails closed. Non-finite
scores, malformed responses, mismatched provider IDs, invalid chunks, or
unauthorized results fail the complete request.

Both searches run concurrently under the overall retrieval deadline. A
deadline expiry cancels and awaits both tasks. A channel failure cancels and
awaits its peer and returns no partial result. Retry delay and retry count
remain bounded by the existing adapter contract. Backend differences stay
explicit: Qdrant and the in-memory store do not pretend to provide BM25 or
hybrid behavior.

## Security, privacy, reliability, and cost

- Authorization is applied before both provider searches through identical
  tenant, classification, role, group, PII-status, ingestion-status, and
  approved-exception filters.
- Every returned chunk is reauthorized before it can cross the adapter
  boundary. A cross-tenant result aborts the complete request rather than
  being silently removed from a partially successful response.
- Raw vendor responses and exceptions do not escape into application schemas,
  citations, or evidence. Existing provider-neutral `Query`, `Chunk`, and
  `RetrievedChunk` models remain the public boundary.
- Collection and retrieval identities prevent a vector-only index from being
  silently treated as a hybrid index, or a hybrid index from being used with a
  different analyzer, embedding, collection, or policy identity.
- Candidate and concurrency limits bound provider work. The retry contract
  bounds a request to four search calls; it does not mean two retries after an
  initial call.
- Local tests used workstation CPU, memory, and disk, whose cost was not
  monetized. No AWS, hosted OpenSearch, paid model, registry, network, cloud,
  deployment, or billing operation ran, so this record supplies no production
  operating-cost evidence.

## Decision and alternatives

**Decision:** add hybrid retrieval inside the existing provider-neutral,
authorization-preserving OpenSearch adapter boundary. Use one immutable policy
and index identity, two bounded concurrent channels, strict per-result
reauthorization, deterministic normalized fusion, and existing cited-result
schemas.

**Rejected alternatives:** a second RAG stack; leaking OpenSearch request or
response objects into business code; lexical search without the existing
authorization filters; authorization only after unrestricted retrieval;
silent fallback from hybrid to vector; partial results when one channel fails;
unbounded candidates, retries, or concurrency; mutable analyzer or weight
selection; and treating local injected-client evidence as live OpenSearch or
AWS proof.

No new ADR is required for this bounded implementation because ADR-003 already
owns the provider-neutral vector-store boundary and ADR-006 already owns
authorization at retrieval. This record captures the W10-specific choice
without duplicating or superseding either decision.

## Learning handover

The owner should be able to explain hybrid retrieval in three layers:

1. **Business:** exact-word matching and semantic matching complement each
   other, but neither may bypass access control.
2. **Architecture:** one authorized adapter runs bounded BM25 and vector
   channels, validates results, and returns the existing provider-neutral
   cited candidates.
3. **Operations:** policy and index identities make mode changes explicit;
   local tests do not prove a live index migration or production relevance.

Suggested owner teach-back questions:

1. Why must the same authorization filters be present in both channels, and
   why is returned-result reauthorization still required?
2. Why normalize each channel before fusion, and what happens when every score
   in one channel is equal?
3. Why does “two attempts” mean at most four provider calls for hybrid search,
   not six?
4. Why must changing vector/hybrid mode use an exactly matching index identity?
5. Which W10 results are local source evidence, and which live OpenSearch,
   migration, performance, lifecycle, and cost facts remain unproved?
